# **2. 탭게임 API호출 최적화**

1. **어뷰징을 최대한 차단하며 동시에 호출비용을 줄이기 위한 중간 지점 설계**
   - **문제:**
     - 탭게임 특성 상 클라이언트 조작을 통한 어뷰징 위험이 존재. 이를 방어해야된다고 팀 논의가 있었음.
   - **조치:**
     - 재화에 관련된 상태를 지속적으로 클라이언트가 오래 쥐고 있는 것은 위험하다고 판단. 클라에 있는 상태를 최대한 빠르게 서버로 보내서 서버를 SSOT로 활용하고자 함.
     - 그러나, 탭(재화를 얻기 위한 액션) 횟수만큼 호출을 발생시키는 비효율과 비용을 감당하기엔 너무 부담이 큼.
     - 연속 탭핑 횟수를 실시간 집계하지만 **마지막 탭 후 3초 뒤에만 서버로 전송하도록 최적화(**디바운스 이용)
       - 만약 사용자가 3초 이내에 화면을 나갈 경우, useEffect cleanup 함수를 사용하여 화면이 꺼지기 전 서버 업데이트 보장
   - **결과:**
     - 탭 횟수마다 서버 호출 하는 것도 막으면서, 3초 내로 서버에 전송 후 민감한 데이터 초기화하는 방어 로직 구현

1. **서버 비용을 낮추기 위해 재화 관련 상태도 더욱 캐싱을 강화하도록 개선**
   - **문제:**
     - 위 디바운스 패턴으로 호출을 줄였지만, 탭핑 API를 더더욱 덜 호출할 수 있도록 캐싱을 강화하자는 비즈니스 요구가 들어옴.
     - 상태를 오래 유지하지 않고 서버 패칭 이후, 클라이언트는 바로 초기화시키는 것이 어뷰징을 막을 수 있는 방법이라 생각했지만 비즈니스 결정 요구에 따르기로 결정.
   - **조치:**
     - 탭 횟수를 persist되는 전역상태로 만듦.
       - 예상치 못한 종료 후에도 앱 재시작 시 얻은 재화를 유지시킬 수 있음
       - **앱 실행 후 초기화 시 전역상태에 있는 캐싱된 재화를 서버에 전송 후 초기화**
     - 게임 플레이 중 캐싱된 재화와 이번 세션 플레이로 얻은 재화를 합산하여 보여주며 관리
   - **결과:**
     - 재화 획득 API 호출 횟수 **65% 감소(백엔드 개발자의 보고 상)**

# **4. 인터랙티브 애니메이션**

1. **미니앱 iframe 성능 한계 최적화 — 수달 연속 탭핑 시 동적인 재화 획득 이펙트가 나오도록 설정하고, 극한의 상황까지 탭핑해도 앱이 끊기지 않도록 최적화 진행**
   - 문제:
     - 유저가 아무리 탭을 해도 재화가 안 쌓인다는 CS가 자주 포착
     - 수달 캐릭터 주변에 재화가 쌓인다는 이펙트가 없고, 메뉴바 상단의 재화량만 늘고 있어서 유저가 인지를 못한 상황
   - 조치:
     - 재화 획득 시 수달 캐릭터 주변에 재화 획득량이 이펙트로 뜨도록 설정
     - 부스트 + 업그레이드 상황을 반영하여 색상과 크기가 바뀌도록 설정
     - 이펙트의 진행 방향도 랜덤하게 설정되도록 함.
     - 점수 스코어가 여러 개 중첩될 수 있도록 하여 탭을 할때마다 여러개의 이펙트가 화면을 덮는 경험을 유저에게 제공
   - 결과:
     - 재화가 늘지 않는다는 CS가 더 이상 들어오지 않음.
   - 2차 문제:
     - 탭할 때마다 문자열이 담길 수 있는 배열 안에 스코어 문자열 컴포넌트를 push시키고, 이를 fade out 마운트 애니메이션으로 보여주도록 구현하였음.
     - 탭을 그만 두면 컴포넌트 배열을 초기화하는데, 한 번에 수백번 탭하는 유저들은 스코어 너무 많아져서 텔레그램 내 성능 한계에 도달함
   - 조치:
     - 여러 테스트를 거쳐, 연속 탭핑 중이라도 배열 인자가 80개에 도달했을 시 5개 정도만 남기고 나머지 인자는 없애기로 결정.
   - 결과:
     - 유저에겐 애니메이션이 진행중인 가장 큰 5개의 유효한 이펙트만 잘 보이면 되고, 거의 사라진 컴포넌트는 탭 중에 청소되어도 아무런 이상을 못 느낌
     - 성능이 한정된 미니앱 위에서 끊김없는 애니메이션 성능을 보장

1. **동적인 룰렛 애니메이션 구현**
   - 문제:
     - 전문 영상 디자이너가 없는 환경이어서, 프론트엔드단에서 룰렛 효과를 그럴듯하게 만들어야한다는 과제를 받음.
     - 룰렛을 돌릴 때, 텔레그램 미니앱의 성능 상 애니메이션 프레임 드롭 발생
   - 조치:
     - 룰렛 애니메이션 시 translate3D, will-change 등 GPU 사용을 유도하는 속성들을 이용하여 부족한 성능을 보완.
     - 룰렛 실행 시 먼저 어떤 아이템이 당첨됐는지 서버에서 패칭해온 다음 애니메이션 시작
   - [애니메이션 구현 과정]:
     - 룰렛판 구성은 서버에서 가져오는 정보. 룰렛판 구성이 동적으로 설정되게 만듦
     - 서버에서 가져온 당첨선택지 배열의 길이를 4배로 늘리고, 4번째 배열에서 당첨 아이템이 룰렛판의 가운데에 오도록 설정. 트랜지션 애니메이션 속도를 마지막에 딜레이 되도록 유도.
     - 결과적으로 유저는 룰렛이 네바퀴 쯤 돌다가 내가 당첨된 아이템 앞에서 감속하여 멈추는 것으로 느끼게 됨.
